# Getting started

**m3-expressive-react** is a Material Design 3 (Expressive) component
library for React with a deliberately MUI-idiomatic API. Appearance,
defaults, and motion follow the MD3 spec and Jetpack Compose `material3`.

## Installation

```bash
npm install m3-expressive-react
```

Requires React 18 or 19.

## Usage

Wrap your app in `ThemeProvider` and import the token stylesheet once:

```tsx
import { ThemeProvider, Button } from 'm3-expressive-react'
import 'm3-expressive-react/styles.css'

export function App() {
  return (
    <ThemeProvider seedColor="#6750A4" mode="light">
      <Button variant="filled" onClick={() => console.log('clicked')}>
        Hello MD3
      </Button>
    </ThemeProvider>
  )
}
```

:::info The stylesheet import is required
`styles.css` carries the design tokens (shape, motion, state, typescale)
every component references. Colors come from `ThemeProvider`, which derives
the full MD3 color-role map (light and dark) from your `seedColor` at
runtime via Dynamic Color.
:::

### Per-component imports

Every component folder is also its own entry point with a **default
export**, MUI-style. A subpath import loads only that component's CSS, so
import the design tokens (`tokens.css`) once instead of `styles.css`:

```tsx
import 'm3-expressive-react/tokens.css' // once, at the app root
import { ThemeProvider } from 'm3-expressive-react'
import Button from 'm3-expressive-react/Button'
import Radio, { RadioGroup } from 'm3-expressive-react/Radio'
import type { ButtonProps } from 'm3-expressive-react/Button'
```

- The **default export** is the component the folder is named after
  (`Button`, `Radio`, `Chip`, `Card`, `Menu`, `Snackbar`, …). Two folders
  have no namesake: `AppBar` → `TopAppBar` and `ProgressIndicator` →
  `LinearProgressIndicator`. Every named export and type of the folder —
  `RadioGroup`, `ChipSet`, `MenuItem`, `SnackbarProvider`, `BottomAppBar`,
  `CircularProgressIndicator`, … — comes from the same subpath.
- **Named imports work too**: `import { Button } from 'm3-expressive-react/Button'`.
- Root and subpath imports **can be mixed**: both resolve to the same
  modules (one `RadioGroup` context, one `ThemeProvider`). The root entry is
  unchanged and its JavaScript is tree-shaken either way.

### CSS options

| You import components from…       | Import this CSS once                                  |
| --------------------------------- | ----------------------------------------------------- |
| `m3-expressive-react` (root)      | `m3-expressive-react/styles.css` — every component    |
| `m3-expressive-react/<Component>` | `m3-expressive-react/tokens.css` — tokens + typescale |

With subpath imports each component module imports its own CSS (plus the
shared Ripple / FocusRing styles); Vite, webpack 5 (with `css-loader`) and
Next.js (app and pages router) bundle it automatically.

:::caution Pick one setup
Don't combine `styles.css` with subpath imports — the components' CSS would
be loaded a second time, which bloats the stylesheet and can reorder the
cascade.
:::

:::note Environments without CSS imports
`require()` (CommonJS, Jest) and server-side Node `import` (the `node`
export condition, e.g. SSR with externalized dependencies) resolve to
CSS-free modules, so tests and server rendering never load a `.css` file;
the client bundle carries the styles. If your bundler cannot import CSS at
all, use the root entry with `styles.css`.
:::

### Next.js App Router

Interactive components and `ThemeProvider` ship with a `'use client'`
directive, so Server Components (`app/layout.tsx`, `app/page.tsx`) can import
them directly, from the root entry or a subpath — no wrapper file needed:

```tsx
// app/layout.tsx (Server Component)
import { ThemeProvider } from 'm3-expressive-react'
import 'm3-expressive-react/styles.css'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <ThemeProvider seedColor="#6750A4" mode="light">
          {children}
        </ThemeProvider>
      </body>
    </html>
  )
}
```

The usual Server Components rule still applies: event handlers (`onClick`,
`onChange`, …) can't be passed from a Server Component, so put interactive
markup in your own `'use client'` component. The presentational `Badge` and
`Divider` and the pure helpers (`generateColorScheme`, `schemeToCssVars`,
`schemeToCssText`, the motion tokens) are server-safe.
