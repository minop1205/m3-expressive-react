# Tabs

MD3 tabs: a `role="tablist"` row of `Tab`s with a sliding active indicator,
in **primary** and **secondary** variants, fixed or scrollable.

## Variants

`primary` tabs sit at the top of a content pane under an app bar and use a
content-width indicator; `secondary` tabs divide content within a pane and
use a full-width line.

      <Tab value="hotels" label="Hotels" />
      <Tab value="explore" label="Explore" />
    </Tabs>


## Icons

`icon` shows above the label (icon + label tabs are 64dp tall).

<Demo>
  <div style={{ width: '100%' }}>
    <Tabs aria-label="Trip with icons" defaultValue="flights">
      <Tab value="flights" icon={<FlightIcon />} label="Flights" />
      <Tab value="hotels" icon={<HotelIcon />} label="Hotels" />
      <Tab value="explore" icon={<ExploreIcon />} label="Explore" />
      <Tab value="disabled" icon={<ExploreIcon />} label="Disabled" disabled />
    </Tabs>
  </div>
</Demo>

`iconPosition="start"` puts the icon before the label instead (8dp gap,
48dp tabs — Compose `LeadingIconTab`). The primary indicator then spans the
icon and the label.

<Demo>
  <div style={{ width: '100%' }}>
    <Tabs aria-label="Trip with leading icons" defaultValue="flights">
      <Tab value="flights" icon={<FlightIcon />} iconPosition="start" label="Flights" />
      <Tab value="hotels" icon={<HotelIcon />} iconPosition="start" label="Hotels" />
      <Tab value="explore" icon={<ExploreIcon />} iconPosition="start" label="Explore" />
    </Tabs>
  </div>
</Demo>

```tsx
<Tab value="flights" icon={<FlightIcon />} iconPosition="start" label="Flights" />
```

`iconPosition` works on both variants, but m3 secondary tabs normally have
no icon (the secondary tab anatomy has none), so prefer text-only secondary
tabs.

## Badges

`badge` takes a childless [`<Badge>`](./badge.mdx): it sits on the icon (stacked or
leading), or 4dp after the label on a text-only tab. The badge takes no layout
space — the label stays centered and the indicator keeps following the label /
icon. Its text (the Badge `label`, or the default `"New notification"` /
`"{n} new notifications"`) is read after the tab label, e.g.
"Hotels 3 new notifications".

<Demo>
  <div style={{ width: '100%', display: 'flex', flexDirection: 'column', gap: 24 }}>
    <Tabs aria-label="Trip with badges" defaultValue="flights">
      <Tab value="flights" icon={<FlightIcon />} label="Flights" badge={<Badge size="small" />} />
      <Tab value="hotels" icon={<HotelIcon />} label="Hotels" badge={<Badge value={3} />} />
      <Tab value="explore" icon={<ExploreIcon />} label="Explore" />
    </Tabs>
    <Tabs aria-label="Inbox" variant="secondary" defaultValue="primary">
      <Tab value="primary" label="Primary" />
      <Tab value="social" label="Social" badge={<Badge value={12} />} />
      <Tab value="updates" label="Updates" badge={<Badge size="small" />} />
    </Tabs>
  </div>
</Demo>

```tsx
<Tab value="hotels" icon={<HotelIcon />} label="Hotels" badge={<Badge value={3} />} />
<Tab value="social" label="Social" badge={<Badge value={12} label="12 unread" />} />
```

## Scrollable

Fixed tabs (default) split the row into equal widths. `scrollable` tabs size
to their content and scroll horizontally; the selected tab is scrolled to
the center whenever the selection changes. Users swipe the row on touch,
use a two-finger horizontal gesture on a trackpad, or roll the **mouse
wheel** over it (m3 Foundations › Inputs) — the wheel scrolls the row
horizontally until it reaches an end, then scrolls the page as usual.

<Demo>
  <div style={{ width: '100%', maxWidth: 480 }}>
    <Tabs aria-label="Categories" scrollable defaultValue="c1">
      {['News', 'Sports', 'Technology', 'Entertainment', 'Science', 'Health', 'Travel', 'Business'].map((l, i) => (
        <Tab key={l} value={`c${i + 1}`} label={l} />
      ))}
    </Tabs>
  </div>
</Demo>

```tsx
<Tabs scrollable value={value} onChange={(event, next) => setValue(next)}>…</Tabs>
```

## With panels

Wrap the tabs and their panels in a `TabContext` and give each `TabPanel`
the `value` of its tab. The tabs and panels are linked automatically
(`id`, `aria-controls`, `aria-labelledby`, following the WAI-ARIA APG Tabs
pattern) and only the selected panel is shown (the others stay mounted with
`hidden`). Put `value` / `defaultValue` / `onChange` on `TabContext`; the
inner `Tabs` takes its selection from there.

<Demo>
  <div style={{ width: '100%' }}>
    <TabContext defaultValue="flights">
      <Tabs aria-label="Trip planner">
        <Tab value="flights" label="Flights" />
        <Tab value="hotels" label="Hotels" />
        <Tab value="explore" label="Explore" />
      </Tabs>
      <TabPanel value="flights" style={{ padding: 16 }}>Search one-way and round-trip flights.</TabPanel>
      <TabPanel value="hotels" style={{ padding: 16 }}>Find a place to stay.</TabPanel>
      <TabPanel value="explore" style={{ padding: 16 }}>Discover things to do nearby.</TabPanel>
    </TabContext>
  </div>
</Demo>

```tsx
const [value, setValue] = useState('flights')

<TabContext value={value} onChange={(event, next) => setValue(next)}>
  <Tabs aria-label="Trip planner">
    <Tab value="flights" label="Flights" />
    <Tab value="hotels" label="Hotels" />
  </Tabs>
  <TabPanel value="flights">…</TabPanel>
  <TabPanel value="hotels">…</TabPanel>
</TabContext>
```

A panel has `tabIndex={0}` by default, so <kbd>Tab</kbd> from the tab list
moves into it (APG, for panels that do not start with a focusable element).
Pass `tabIndex={-1}` when the panel starts with a focusable element. m3 and
Compose do not specify panels; this part follows the WAI-ARIA APG.

## Navigation tabs

`href` makes a tab a link: m3's *navigation tabs* "invoke navigation to a
new destination". It renders `<a role="tab" href>` with the same look and
keyboard behavior, and is selected through the `Tabs` `value` (usually
derived from the current route). The navigation is not intercepted: the
browser follows the link, and `onChange` fires first, so a client-side
router can call `event.preventDefault()` there and navigate itself.
Ctrl / ⌘ / Shift / Alt clicks open the link elsewhere and do not change the
selection. `target`, `rel` and `download` are passed to the `<a>`.

export function NavigationDemo() {
  const [path, setPath] = useState('/overview')
  return (
    <div style={{ width: '100%' }}>
      <Tabs
        aria-label="Documentation"
        value={path}
        onChange={(event, next) => {
          event.preventDefault()
          setPath(next)
        }}
      >
        <Tab value="/overview" href="#overview" label="Overview" />
        <Tab value="/guides" href="#guides" label="Guides" />
        <Tab value="/api" href="#api" label="API" />
      </Tabs>
    </div>
  )
}

<Demo>
  <NavigationDemo />
</Demo>

```tsx
// React Router
const { pathname } = useLocation()
const navigate = useNavigate()

<Tabs
  aria-label="Account"
  value={pathname}
  onChange={(event, next) => {
    event.preventDefault()
    navigate(next)
  }}
>
  <Tab value="/account/profile" href="/account/profile" label="Profile" />
  <Tab value="/account/billing" href="/account/billing" label="Billing" />
</Tabs>
```

Link tabs have no panel (the destination is the page), so they never get
`aria-controls`. They do not set `aria-current="page"`: in a tab list the
current item is conveyed by `aria-selected` (ARIA 1.2 advises against using
`aria-current` in its place), and setting both makes screen readers announce
it twice. Pass `aria-current` yourself if you need it. For plain site
navigation without a tab look, a `<nav>` of links with `aria-current` is the
more common pattern.

## Container color

The row container is `surface` for both variants. Set the
`--md-tabs-container-color` custom property on the `Tabs` element (or an
ancestor) to match the surface the tabs sit on, e.g. inside a dialog or a
card (Compose `TabRow containerColor`).

<Demo>
  <div style={{ width: '100%', padding: 16, borderRadius: 12, background: 'var(--md-sys-color-surface-container-high)' }}>
    <Tabs
      aria-label="On a container"

      defaultValue="flights"

      <Tab value="flights" label="Flights" />
      <Tab value="hotels" label="Hotels" />

## Accessibility

- `role="tablist"` of `role="tab"` buttons (or links, with `href`) with
  `aria-selected`; label the list with `aria-label`. Inside a `TabContext`,
  tabs and `TabPanel`s are linked with `aria-controls` / `aria-labelledby`.
- **Manual activation** (WAI-ARIA APG): <kbd>←</kbd> / <kbd>→</kbd>
  (mirrored in RTL), <kbd>Home</kbd> and <kbd>End</kbd> move focus only;
  <kbd>Space</kbd> / <kbd>Enter</kbd> select the focused tab and fire
  `onChange`. Arrow keys never fire `onChange`, and neither does activating
  the already-selected tab or a tab whose `onClick` called
  `event.preventDefault()`. Link tabs activate with <kbd>Space</kbd> as well
  as <kbd>Enter</kbd>.
- Automatic activation (arrows select) is not offered: the m3 accessibility
  guidance specifies arrows = focus, <kbd>Space</kbd> / <kbd>Enter</kbd> =
  activate.
- A `badge` is decorative on screen; its text is appended to the tab's
  accessible name after the label. Localize it with the Badge `label` prop.
  For an icon-only tab named with `aria-label`, include the badge in that
  label yourself.
- Roving tabindex: <kbd>Tab</kbd> enters the list on the selected tab and
  leaves it in one step.
