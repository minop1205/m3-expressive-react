# List

MD3 (Expressive) list: a vertical `<ul>` of one-, two- and three-line items
with leading and trailing slots, clickable rows with separately focusable
trailing controls, single / multiple selection, and a segmented variant.

## Lines

Items size themselves to one line (56dp), two lines (72dp) or three lines
(88dp) from the presence of `overline` / `supportingText`; supporting text
that wraps also makes the item three-line.

<Demo>
  <List style={{ width: 360 }}>
    <ListItem headline="One-line item" />
    <ListItem headline="Two-line item" supportingText="Supporting text" />
    <ListItem
      overline="Overline"
      headline="Three-line item"
      supportingText="Supporting text that is long enough to wrap onto a second line"
    />
  </List>
</Demo>

```tsx
<List>

  <ListItem headline="Two-line item" supportingText="Supporting text" />
  <ListItem overline="Overline" headline="Three-line item" supportingText="…" />
</List>
```

## Leading and trailing content

`leading` takes an icon, avatar, image or video; `trailing` an icon or
control; `trailingSupportingText` a right-aligned label. Give decorative
icons `aria-hidden` and images an `alt`.

## Clickable rows

`onClick` makes a row actionable: its leading slot and text become one
native `<button>` covering the row (ripple, focus ring). `href` renders an
`<a>` instead. `selected` applies the secondary-container fill and
`disabled` dims the row to 38%.

<Demo>
  <List style={{ width: 360 }} aria-label="Folders">
    <ListItem headline="Inbox" supportingText="Clickable" onClick={() => {}} />
    <ListItem headline="Drafts" supportingText="Selected" selected onClick={() => {}} />
    <ListItem headline="Documentation" supportingText="Link" href="#clickable-rows" />
    <ListItem headline="Archive" supportingText="Disabled" disabled onClick={() => {}} />
  </List>
</Demo>

```tsx
<ListItem headline="Inbox" onClick={() => openFolder('inbox')} />
<ListItem headline="Documentation" href="/docs" />
```

## Rows with trailing controls

On a clickable row, `trailing` is rendered **beside** the primary action,
not inside it, so a Switch or icon button there stays its own control. A
static row can hold a control in its leading slot, such as a Checkbox.

<Demo>
  <List style={{ width: 360 }} aria-label="Connections">
    <ListItem
      leading={<Icon d={WIFI} />}
      headline="Wi-Fi"
      supportingText="Opens network settings"
      onClick={() => {}}
      trailing={<Switch aria-label="Wi-Fi" defaultSelected />}
    />
    <ListItem
      leading={<Icon d={STAR} />}
      headline="Favorites"
      supportingText="Row and menu are separate actions"
      onClick={() => {}}
      trailing={<IconButton variant="standard" icon={<Icon d={MORE} />} aria-label="More options" />}
    />
    <ListItem
      leading={<Checkbox aria-label="Share usage data" />}
      headline="Share usage data"
      supportingText="Static row with a leading checkbox"
    />
  </List>
</Demo>

## Selection

Set `selectionMode="single"` or `"multiple"` and give each `ListItem` a
`value`; the list owns the state through `value` / `defaultValue` /
`onChange(event, value)`. Selection should not rely on color alone — add a
check or radio indicator.

export function SingleSelectDemo() {
  const [value, setValue] = useState('wifi')
  return (
    <List
      selectionMode="single"
      value={value}
      onChange={(event, next) => setValue(next)}
      aria-label="Preferred network"
      style={{ width: 300 }}
    >
      {[
        ['wifi', 'Wi-Fi'],
        ['ethernet', 'Ethernet'],
        ['cellular', 'Cellular'],
      ].map(([v, label]) => (
        <ListItem
          key={v}
          value={v}
          headline={label}
          leading={<Icon d={value === v ? RADIO_ON : RADIO_OFF} />}
        />
      ))}
    </List>
  )
}

export function MultiSelectDemo() {
  const [value, setValue] = useState(['bt'])
  return (
    <List
      selectionMode="multiple"
      value={value}
      onChange={(event, next) => setValue(next)}
      aria-label="Enabled radios"
      style={{ width: 300 }}
    >
      {[
        ['bt', 'Bluetooth'],
        ['nfc', 'NFC'],
        ['gps', 'Location'],
      ].map(([v, label]) => (
        <ListItem
          key={v}
          value={v}
          headline={label}
          trailing={value.includes(v) ? <Icon d={CHECK} /> : null}
        />
      ))}
      <ListItem value="uwb" headline="Ultra-wideband" supportingText="Unavailable" disabled />
    </List>
  )
}

## Segmented

`variant="segmented"` renders each item as its own surface-colored segment,
2dp apart, with 16dp outer corners on the first and last item. It works
with clickable rows and selection lists alike.


## Accessibility

- The focusable rows share **one Tab stop** (the selected row, else the
  first, then the last focused one). **Down / Right** and **Up / Left** move
  between rows, wrapping at the ends (mirrored in RTL); **Home / End** jump
  to the ends.
- Controls in a row's trailing slot — and in the leading slot of a static
  row — stay Tab stops and are part of the arrow sequence; controls that use
  arrow keys themselves (text inputs, sliders, radios) keep them.
- A clickable row's primary action is a native `<button>` / `<a>`: `role`,
  `tabIndex`, `onKeyDown` and `aria-*` props land on that element.
- With a `selectionMode`, the list is a `listbox` (label it with
  `aria-label`) and its items are `option`s with `aria-selected`; Enter /
  Space or a click selects. Options cannot hold interactive controls.
