# NavigationRail

MD3 Expressive navigation rail for medium and larger windows: a 96dp
**collapsed** column of destinations that morphs on a spring into an
**expanded** rail (icon beside label, 220–360dp wide), either in-flow or as
a **modal** overlay.

export const items = (
  <>
    <NavigationRailItem value="inbox" icon={<InboxIcon />} selectedIcon={<InboxFillIcon />} label="Inbox" />
    <NavigationRailItem value="outbox" icon={<OutboxIcon />} selectedIcon={<OutboxFillIcon />} label="Outbox" badge="3" />
    <NavigationRailItem value="favorites" icon={<FavoriteIcon />} selectedIcon={<FavoriteFillIcon />} label="Favorites" badge />
    <NavigationRailItem value="trash" icon={<DeleteIcon />} selectedIcon={<DeleteFillIcon />} label="Trash" />
  </>
)

export function Header({ expanded, onMenuClick }) {
  return (
    <>
      <IconButton
        variant="standard"
        size="md"
        icon={expanded ? <MenuOpenIcon /> : <MenuIcon />}
        aria-label={expanded ? 'Collapse navigation' : 'Expand navigation'}
        aria-expanded={expanded}
        onClick={onMenuClick}
      />
      <Fab icon={<EditIcon />} label="Compose" followContainer disableElevation />
    </>
  )
}

export function Frame({ children }) {
  // `transform` makes this box the containing block of the modal rail's
  // fixed scrim, so the demo overlay stays inside the frame.
  return (
    <div
      style={{
        position: 'relative',
        display: 'flex',
        width: '100%',
        height: 600,
        overflow: 'hidden',
        transform: 'translateZ(0)',
        borderRadius: 8,
        border: '1px solid var(--md-sys-color-outline-variant)',
      }}
    >
      {children}
    </div>
  )
}

export function Page({ text }) {
  return <div style={{ flex: 1, padding: 24, minWidth: 0 }}>{text}</div>
}

export function RailDemo({ modal, hideOnCollapse, arrangement, footer, initial = 'collapsed' }) {
  const [value, setValue] = useState('inbox')
  const [variant, setVariant] = useState(initial)
  const expanded = variant === 'expanded'
  const toggle = () => setVariant(expanded ? 'collapsed' : 'expanded')
  return (
    <Frame>
      <NavigationRail
        aria-label="Mail"
        value={value}
        onChange={(_event, v) => {
          setValue(v)
          if (modal) setVariant('collapsed')
        }}
        variant={variant}
        arrangement={arrangement}
        modal={modal}
        hideOnCollapse={hideOnCollapse}
        onClose={() => setVariant('collapsed')}
        header={<Header expanded={expanded} onMenuClick={toggle} />}
        footer={footer}
      >
        {items}
      </NavigationRail>
      <Page
        text={
          hideOnCollapse ? (
            <IconButton variant="standard" icon={<MenuIcon />} aria-label="Open navigation" onClick={toggle} />
          ) : modal ? (
            'Expanded, the modal rail overlaps this content with a scrim. Press Escape or click the scrim to collapse it.'
          ) : (
            'Use the menu button to expand and collapse the rail.'
          )
        }
      />
    </Frame>
  )
}

## Collapsed and expanded

`variant` switches between `collapsed` (icon over label) and `expanded`
(icon beside label in a pill, as wide as the widest destination). The change
is a spring morph. The optional `header` is pinned at the top — typically a
menu button and a FAB; `<Fab followContainer>` morphs in sync with the rail.

<Demo>
  <RailDemo />
</Demo>

```tsx
const [expanded, setExpanded] = useState(false)

<NavigationRail
  aria-label="Mail"
  variant={expanded ? 'expanded' : 'collapsed'}
  value={value}
  onChange={(event, next) => setValue(next)}
  header={
    <>
      <IconButton
        variant="standard"
        icon={expanded ? <MenuOpenIcon /> : <MenuIcon />}
        aria-label={expanded ? 'Collapse navigation' : 'Expand navigation'}
        onClick={() => setExpanded(!expanded)}
      />
      <Fab icon={<EditIcon />} label="Compose" followContainer />
    </>
  }
>
  <NavigationRailItem value="inbox" icon={<InboxIcon />} selectedIcon={<InboxFillIcon />} label="Inbox" />
  <NavigationRailItem value="outbox" icon={<OutboxIcon />} label="Outbox" badge="3" />
</NavigationRail>
```

`selectedIcon` shows the filled icon for the active destination. `badge`
takes content for a large badge or `true` for a dot; `badgeLabel` overrides
the announced text.

## Arrangement

`arrangement` places the destinations at the `top` (default), `center`, or
`bottom` below the header.

</Demo>

## Footer

`footer` pins content to the bottom of the rail — the place for low-priority
actions such as a theme toggle, settings or sign-in (m3: "secondary
destinations or actions that have lower priority than the main navigation
items"). It renders inside the `<nav>`, after the destinations, so it is part
of the modal rail's dialog and scrolls with the rail; `arrangement` places
the destinations between header and footer.

`NavigationRailAction` is a destination-like action for the header or
footer: icon, label and badge laid out and morphing exactly like a
`NavigationRailItem`, but never selected (no `aria-current`, no active pill,
it does not change the rail's `value`) — handle it with `onClick`.

<Demo>
  <RailDemo
    footer={
      <>
        <NavigationRailAction icon={<SettingsIcon />} label="Settings" />
        <NavigationRailAction icon={<DarkModeIcon />} label="Dark mode" />
        <NavigationRailAction icon={<LoginIcon />} label="Sign in" badge="2" />
      </>
    }
  />
</Demo>

```tsx
<NavigationRail
  header={…}
  footer={
    <>
      <NavigationRailAction icon={<SettingsIcon />} label="Settings" onClick={openSettings} />
      <NavigationRailAction icon={<DarkModeIcon />} label="Dark mode" onClick={toggleTheme} />
    </>
  }
>
  …destinations
</NavigationRail>
```

Other header / footer content can follow the expand motion through the
public custom property **`--md-navigation-rail-expansion`** (0 = collapsed →
1 = expanded, inherited from the rail; `<Fab followContainer>` uses the same
value), e.g. a logotype beside the logo:

```css
.logotype {
  opacity: calc((var(--md-navigation-rail-expansion, 0) - 0.77) * 5.5);
}
```

Spec note: this is a web adaptation. m3's anatomy has only a menu button and a
FAB besides the destinations, and Compose's `WideNavigationRail` has only a
`header` slot. m3 keeps the menu button and the FAB top-aligned ("Avoid
placing the FAB below navigation items") — put those in `header`, not in
`footer`. Ruling B57.

## Modal

With `modal`, the expanded rail overlaps the page instead of pushing it: a
scrim, focus trapped inside, the rest of the page inert, and
<kbd>Escape</kbd> / scrim click call `onClose`. Collapsed, it is a regular
96dp rail.

<Demo>
  <RailDemo modal />
</Demo>

```tsx
<NavigationRail
  modal
  variant={expanded ? 'expanded' : 'collapsed'}
  onClose={() => setExpanded(false)}
  …
/>
```

## Hide on collapse

`modal` + `hideOnCollapse` hides the rail entirely while collapsed; expanding
slides it in from the leading edge — open it from a button in the page.

<Demo>
  <RailDemo modal hideOnCollapse />
</Demo>

```tsx
<IconButton icon={<MenuIcon />} aria-label="Open navigation" onClick={() => setExpanded(true)} />
<NavigationRail
  modal
  hideOnCollapse
  variant={expanded ? 'expanded' : 'collapsed'}
  onClose={() => setExpanded(false)}
  …
/>
```

## Accessibility

- Renders a `<nav>` landmark — give it an `aria-label`. Items are native
  `<button>`s; the active one carries `aria-current="page"`.
- Tab order: header (menu button, FAB) first, then the destinations, then the
  footer. `NavigationRailAction`s are plain buttons without `aria-current`.
- Badges are announced after the label (`badgeLabel` to customize). An item
  without a `label` needs an `aria-label`.
- The open modal rail is a `dialog` (`aria-modal`) named by `modalLabel`
  (default "Navigation rail"); focus returns to the opener when it
  collapses.
- Initial focus (modal): an element that React's `autoFocus` focused inside
  the rail, else the element marked `data-autofocus`, else the first
  tabbable element. `autoFocus` only runs when its element mounts, so for
  content rendered while the rail is collapsed (the usual `variant={expanded ? 'expanded' : 'collapsed'}` pattern)
  mark the target with `data-autofocus` instead.
- A modal rail mounted expanded plays the same expand motion as one expanded later.
