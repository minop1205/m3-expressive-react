# Dialog

MD3 basic dialog: focus is trapped inside, <kbd>Escape</kbd> and scrim
click close it, and focus returns to the opener on close.

export function DialogDemo() {
  const [open, setOpen] = useState(false)
  return (
    <>
      <Button variant="filled" onClick={() => setOpen(true)}>
        Open dialog
      </Button>
      <Dialog
        open={open}
        onClose={() => setOpen(false)}
        title="Reset settings?"
        actions={
          <>
            <Button variant="text" onClick={() => setOpen(false)}>Cancel</Button>
            <Button variant="text" onClick={() => setOpen(false)}>Reset</Button>
          </>
        }
      >
        This restores the default configuration. Your data is kept.
      </Dialog>
    </>
  )
}

## Full-screen

`fullScreen` covers the viewport with a top bar — a close button, the
`title`, and `actions` at the end — over full-bleed content. It has no
scrim; the close button and <kbd>Escape</kbd> call `onClose`. Use it on
compact screens for tasks with several inputs.

export function FullScreenDemo() {
  const [open, setOpen] = useState(false)
  return (
    <>
      <Button variant="outlined" onClick={() => setOpen(true)}>
        Open full-screen dialog
      </Button>
      {/* The open dialog is drawn in the top layer, above the docs navbar. */}
      <Dialog
        open={open}
        fullScreen
        onClose={() => setOpen(false)}
        title="New event"
        actions={<Button variant="text" onClick={() => setOpen(false)}>Save</Button>}
      >
        <div style={{ display: 'flex', flexDirection: 'column', gap: 16, paddingTop: 8 }}>
          <TextField variant="outlined" label="Title" />
          <TextField variant="outlined" label="Location" />
          <TextField variant="outlined" multiline label="Notes" />
        </div>
      </Dialog>
    </>
  )
}

## Long content

When the content doesn't fit, only the body scrolls: the icon and headline
stay pinned at the top and the actions at the bottom (m3: "Even when
scrolling is required, the dialog title is pinned at the top, with buttons
pinned at the bottom"; Compose `AlertDialog` shrinks only its text slot). A
full-screen dialog keeps its top bar and scrolls the content below it. No
divider is added — m3 makes it optional; put a `<Divider>` in the content
if you want one.

export function LongDialogDemo() {
  const [open, setOpen] = useState(false)
  return (
    <>
      <Button variant="outlined" onClick={() => setOpen(true)}>
        Open terms
      </Button>
      <Dialog
        open={open}
        onClose={() => setOpen(false)}
        title="Terms of service"
        actions={
          <>
            <Button variant="text" onClick={() => setOpen(false)}>Decline</Button>
            <Button variant="text" onClick={() => setOpen(false)}>Accept</Button>
          </>
        }
      >
        {Array.from({ length: 16 }, (_, i) => (
          <p key={i}>
            Section {i + 1}. By using this service you agree to keep your account
            details accurate and to use the service lawfully.
          </p>
        ))}
      </Dialog>
    </>
  )
}

## Width

A basic dialog is 280–560px wide (the m3 range, as Compose `AlertDialog`).
Change the range with two CSS custom properties, on the dialog (`style` /
`className`) or any ancestor:

| Custom property | Default |
| --- | --- |
| `--md-dialog-container-min-width` | `280px` |
| `--md-dialog-container-max-width` | `560px` |

Values outside 280–560px are outside the m3 spec (m3 doesn't define custom
widths). A full-screen dialog covers the viewport and ignores them.

export function NarrowDialogDemo() {
  const [open, setOpen] = useState(false)
  return (
    <>
      <Button variant="outlined" onClick={() => setOpen(true)}>
        Open narrow dialog
      </Button>
      <Dialog
        open={open}
        onClose={() => setOpen(false)}
        title="Rename file"
        style={{ '--md-dialog-container-max-width': '320px' }}
        actions={<Button variant="text" onClick={() => setOpen(false)}>Done</Button>}
      >
        This dialog is capped at 320px.
      </Dialog>
    </>
  )
}

## Initial focus

On open, focus goes to an element that React's `autoFocus` focused inside
the dialog, else the element marked `data-autofocus`, else the first
tabbable element. `autoFocus` only runs when its element mounts — and with
the usual `open={open}` pattern the content mounts while the dialog is still
closed — so mark the target with `data-autofocus` instead:

```tsx
<Dialog
  open={open}
  onClose={() => setOpen(false)}
  title="Discard draft?"
  actions={
    <>
      {/* The safe action takes focus on open. */}
      <Button variant="text" data-autofocus onClick={() => setOpen(false)}>
        Cancel
      </Button>
      <Button variant="text" onClick={discard}>Discard</Button>
    </>
  }
/>
```

A dialog mounted with `open` (rendered only while open) can use `autoFocus`,
and plays the same open motion as one opened later.

## Stacking

While open, the dialog is drawn in the browser's top layer, so app
`z-index`, `transform` and `overflow` can't clip or cover it, and it paints
above popups opened before it — such as the [Menu](./menu) item that opened
it. A Menu opened inside the dialog paints above the dialog, and snackbars
from `SnackbarProvider` stay above both. The dialog keeps its place in the
DOM, so `ThemeProvider` tokens apply as usual. The same holds for the modal
sheets, drawer, rail and pickers. Browsers without the Popover API fall back
to `z-index`.

:::warning Upgrading from 1.4 or earlier
Before 1.5.0 (#494) these modals were not in the top layer. If your app
wrapped a Dialog, a modal sheet / drawer / rail or a modal DatePicker /
TimePicker in its own popover or top-layer container to lift it above other
layers, remove that wrapper: the app's layer would be painted above the modal
and block it.
:::
