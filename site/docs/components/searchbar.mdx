# SearchBar

MD3 search bar: a 56dp field that, given results as `children`,
opens a search view — docked under the bar, or full-screen (`layout`).

## Basic

Without `children` the component is a plain search field. `onSearch` fires
on Enter (not while an IME composition is being committed).

<Demo>
  <SearchBar aria-label="Search" placeholder="Search messages" onSearch={(q) => console.log(q)} />
</Demo>

```tsx
<SearchBar aria-label="Search" placeholder="Search messages" onSearch={(query) => runSearch(query)} />
```

## Search view with results

Pass results as `children` — typically a `List` of clickable `ListItem`s.
The view opens on focus (or ArrowDown) and closes on Escape, an outside
click, or a scrim click. It renders in the top layer, pinned under the bar,
so ancestors' `overflow` can't clip it.

export const FRUITS = ['Apple', 'Apricot', 'Banana', 'Blueberry', 'Cherry', 'Grape', 'Mango', 'Orange']

export function SearchViewDemo() {
  const [query, setQuery] = useState('')
  const [open, setOpen] = useState(false)
  const matches = FRUITS.filter((f) => f.toLowerCase().includes(query.toLowerCase()))
  return (
    <div style={{ width: '100%', maxWidth: 480 }}>
      <SearchBar
        aria-label="Search fruit"
        placeholder="Search fruit"
        value={query}
        onChange={(event, next) => setQuery(next)}
        open={open}
        onOpenChange={setOpen}
        suggestionsLabel="Suggestions below"
        endIcon={
          query ? (
            <IconButton
              variant="standard"
              aria-label="Clear search"
              icon={<CloseIcon />}
              onClick={() => setQuery('')}
            />
          ) : undefined
        }
      >
        <List>
          {matches.map((fruit) => (
            <ListItem
              key={fruit}
              headline={fruit}
              onClick={() => {
                setQuery(fruit)
                setOpen(false)
              }}
            />
          ))}
        </List>
      </SearchBar>
    </div>
  )
}

The open state follows the usual pattern: `open` + `onOpenChange` for
controlled, `defaultOpen` for uncontrolled. Likewise the query: `value` +
`onChange(event, value)`, or `defaultValue`.

## Full-screen layout

`layout="fullscreen"` opens the results in a modal view covering the
viewport — the layout MD3 recommends on compact (phone) screens; `docked`
(the default) suits larger ones. Clicking the bar, typing or ArrowDown
expands it: the field moves to the top with a back button in place of the
search icon, and the results fill the space below. Focus stays inside the
view; Escape or the back button collapses it and focus returns to the bar.
Name the back button with `backLabel` (default `'Back'`). The layout doesn't
switch by itself — pick it per window size, e.g.
`layout={isCompact ? 'fullscreen' : 'docked'}` with a
`matchMedia('(max-width: 599px)')` hook.

export function FullScreenDemo() {
  const [query, setQuery] = useState('')
  const [open, setOpen] = useState(false)

    <div style={{ width: '100%', maxWidth: 480 }}>

        placeholder="Search fruit"
        layout="fullscreen"

        onChange={(event, next) => setQuery(next)}
        open={open}
        onOpenChange={setOpen}

The view uses the Expressive contained style (Compose
`ExpandedFullScreenContainedSearchBar`): the field keeps its rounded shape on a
surface-container-low page, with no divider. It is drawn in the top layer,
so it also works inside a `TopAppBar variant="search"`. `onChange`,
`onSearch` and `onKeyDown` follow the field you type in; `onFocus`,
`onBlur` and `inputRef` stay on the bar's input.

## Leading and trailing slots

`startIcon` replaces the default search glyph and `endIcon` adds a trailing
control. Both are 48dp slots, so an `IconButton` (back, menu, voice search,
clear…) fits and stays in the tab order. Mark a purely decorative custom
icon `aria-hidden` yourself.

<Demo>
  <SearchBar
    aria-label="Search"
    startIcon={<IconButton variant="standard" aria-label="Back" icon={<ArrowBackIcon />} />}
    endIcon={<IconButton variant="standard" aria-label="Clear" icon={<CloseIcon />} />}
  />
</Demo>

```tsx
  startIcon={<IconButton variant="standard" aria-label="Back" icon={<ArrowBack />} />}
  endIcon={<IconButton variant="standard" aria-label="Voice search" icon={<Mic />} />}
/>
```

## The native input

`ref` and extra props land on the root (`role="search"` landmark). Use
`inputRef` for the native `<input>`, and `inputProps` for attributes without
a dedicated prop — the component's own wiring wins on conflicts.

```tsx
<SearchBar inputRef={inputRef} inputProps={{ 'aria-label': 'Search docs', maxLength: 80 }} />
```

## Accessibility

- The root is a `role="search"` landmark. With results the input becomes an
  APG `combobox` (`aria-expanded`, `aria-controls`,
  `aria-autocomplete="list"`); otherwise it is a native search input.
- Keyboard: ArrowDown opens the view and moves into the results;
  ArrowUp / ArrowDown / Home / End move between result items (ArrowUp from
  the first returns to the input); Escape closes the view and returns focus
  to the input; Enter calls `onSearch`. Moving focus out closes the view.
- Opening the view is announced through a polite live region with
  `suggestionsLabel` (default `'Suggestions below'`) — localize it with the
  rest of your strings.
- Full-screen layout: the bar's input opens a modal `role="dialog"`
  (`aria-haspopup="dialog"`) and doesn't open on Tab focus alone. Inside it,
  focus is trapped and the rest of the page is inert; the field is a
  combobox for the results (same arrow keys as above). Escape or the back
  button closes it and focus returns to the bar.
- A consumer `onKeyDown` that calls `preventDefault()` opts out of the
  built-in handling for that key.
